# Audit Log Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land a contractual PropertyDO `audit_log` (attribution + same-txn durability), retire hollow `audit.append`, and enforce entitled-command writer coverage by a catalog-derived registry test.

**Architecture:** v17 creates append-only `audit_log` (diff envelope, actor `NOT NULL`). Mutations call private `appendAuditLogSync` inside the same `transactionSync` as the money/inventory write. Catalog entry `audit.append` is deleted; prototype action `ADD_AUDIT_LOG` stays in `PROTOTYPE_ACTIONS` via an exported side-effect exemption. No `audit.recorded` queue event.

**Tech Stack:** Cloudflare Durable Objects, TypeScript, vitest / `@cloudflare/vitest-pool-workers`, existing `gatePermission` / `runIdempotent` / `V1_HTTP_ROUTE_AUDIT` / `property-ddl.mjs` patterns.

**Spec:** [`docs/superpowers/specs/2026-08-07-audit-log-design.md`](../specs/2026-08-07-audit-log-design.md)

## Global Constraints

- **Own table, not outbox.** Outbox permanence is accidental — never base compliance on it. No `actor` columns on `outbox` this slice.
- **Same `transactionSync` as the mutation** — committed money change ⇔ audit row (or neither). Best-effort after-commit appends are forbidden.
- **Retire dispatchable `audit.append`** — delete from `COMMAND_CATALOG`; private helper only; no HTTP mutate route; no `REPLAY_DISPATCH`.
- **Do not shrink `PROTOTYPE_ACTIONS`** — still length 35, still includes `ADD_AUDIT_LOG`. Coverage via `PROTOTYPE_ACTIONS_AS_SIDE_EFFECT`.
- **Actor `NOT NULL`** — `userId` or `system:<reason>` (same as `property_config_audit`).
- **Diff envelope** — `before_json` nullable, `after_json` NOT NULL; ids only, no guest PII.
- **`audit_log` must never be silently pruned** — document in migration header comment; `ARCHIVE` owns future purge (not implemented here).
- **Scoping rule is tested** — every entitled catalog command is in `AUDIT_WRITER_COMMAND_IDS` or `AUDIT_WRITER_EXEMPTIONS` (exported constants with reason strings). New entitled commands fail CI until registered.
- **Remove `audit.recorded`** from consumer; do not emit it.
- **Migration head v17**; touch `scripts/property-ddl.mjs`.
- **Route `get_audit_log`** at `V1_HTTP_ROUTE_AUDIT[61]` **and** `V1_ROUTES` (same order). Permission `folio:read`; entitlement `pms.core`; `degradedRead: 'FAIL_CLOSED'`; no `commandId`.
- **TDD** where noted; commit after each task.
- **Always commit when a task is done.**

```ts
private auditAppendFaultForTest = false;

setAuditAppendFaultForTest(fault: boolean): void {
  this.auditAppendFaultForTest = fault;
}

/** Sync — must be called inside the mutation's transactionSync. */
private appendAuditLogSync(input: {
  at?: number;
  actor: string;
  commandId: string;
  entityType: string;
  entityId: string;
  beforeJson?: unknown | null;
  afterJson: unknown;
  shiftId?: string | null;
  reservationId?: string | null;
}): void {
  if (this.auditAppendFaultForTest) {
    throw new Error('audit_append_fault_for_test');
  }
  if (!input.actor) throw new Error('audit_actor_required');
  const at = input.at ?? Date.now();
  this.ctx.storage.sql.exec(
    `INSERT INTO audit_log (
       at, actor, command_id, entity_type, entity_id,
       before_json, after_json, shift_id, reservation_id, created_at
     ) VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?)`,
    at,
    input.actor,
    input.commandId,
    input.entityType,
    input.entityId,
    input.beforeJson == null ? null : JSON.stringify(input.beforeJson),
    JSON.stringify(input.afterJson),
    input.shiftId ?? null,
    input.reservationId ?? null,
    at,
  );
}

private auditActorSync(actor: ActorContext): string {
  return actor.kind === 'user' ? actor.userId : `system:${actor.reason}`;
}
```
